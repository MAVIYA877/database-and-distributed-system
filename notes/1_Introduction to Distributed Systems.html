What is a Distributed System?

Simple definition: A distributed system is a collection of independent computers that communicate over a network and work together to provide a common service.

Real-life Example: Food Delivery

When a customer orders food, the user sees one application, but internally many services cooperate — often running on entirely different machines.

Why Do We Need Distributed Systems?Six core motivations organizations rely on

📈 Scalability

More users → more machines. Horizontal scaling lets capacity grow with demand.

1 Server → 100 users ⟶ 10 Servers → 100,000 users

🟢 Availability

If one server fails, another continues serving requests — no total outage.

⚡ Performance

Work can be divided among multiple machines and processed in parallel.

🌍 Geographic Distribution

Users from India, Europe and America can access infrastructure near them, reducing latency.

🔗 Resource Sharing

Computers can share critical resources across the network.

filesdatabasesCPU storageservicesnetwork

🛡 Fault Tolerance

The system continues operating despite partial failures — resilience by design.

First Java DemonstrationA simple simulation — start here before real distribution

We'll simulate three "servers" as Java objects handling different orders. This models the idea of distribution without machines actually being distributed yet — that distinction matters.

Step-by-Step Implementation

Create the Server class

Represents a single server node with a name and a method to process incoming requests.

Add a constructor

Each Server instance is initialized with an identifying name (e.g. "Server-1").

Implement processRequest()

Prints which server is handling which request — simulating request routing.

Create the Demo class with main()

Instantiate three servers and dispatch one order to each.

Compile & run

Use javac then java to observe each order routed to a distinct simulated server.

Server.java
public class Server {
    private String name;

    public Server(String name) {
        this.name = name;
    }

    public void processRequest(String request) {
        System.out.println(name + " processing: " + request);
    }
}
DistributedSystemDemo.java
public class DistributedSystemDemo {
    public static void main(String[] args) {
        Server server1 = new Server("Server-1");
        Server server2 = new Server("Server-2");
        Server server3 = new Server("Server-3");

        server1.processRequest("Order #101");
        server2.processRequest("Order #102");
        server3.processRequest("Order #103");
    }
}
Console Output Server-1 processing: Order #101
Server-2 processing: Order #102
Server-3 processing: Order #103
Request Routing (Simulated)

⚠ This is only a simulation running in one JVM process — the "servers" are not actually on separate machines yet.

💬 Discussion Question

"If Google Search were running on only one computer, what problems would occur?"

Expected points:
  • Huge load — a single machine can't handle billions of queries.
  • Poor availability — any downtime takes the whole service offline.
  • Limited storage — the entire search index can't fit on one machine.
  • Slow response — no parallelism means high latency for users worldwide.
  • Single point of failure — one crash halts the entire system.
  • Difficult scaling — no way to add capacity as demand grows.
